Homebench

How the benchmark works

A distributed stress harness for shared filesystems: one controller orchestrates many clients that create, delete, read, and write on a common mount — then reports IOPS, bandwidth, and latency.

Architecture

Controller · UI · clients

Controller

Holds config, drives phase order, aggregates metrics, serves the Web UI (default :8080).

Web UI

Live WebSocket snapshot: clients, charts, latency histograms, results, export.

Clients

Register over WebSocket, receive phase commands, run IO on the shared FS, push metrics.

Data path

IO goes to the filesystem, not through the controller. Prefix = hash(hostname) % N.

Layout

Where work lands on the shared FS

<prefix>/<test>/software/ shared assets (package, git bundle, archive) <prefix>/<test>/<hostname>/ private tree per client ├─ git/ · untar/ timed software ops └─ shards / files create · delete · R/W
  • Controller prepares shared software/ once (unpack / bundle / download).
  • Clients time clone / untar into their own <hostname>/ dirs.
  • Hostname can be overridden with -hostname — that string names the private tree.

Run flow

Phases in order

  • Software cold/warmStartup command from shared package
  • Git cloneClone from shared repo.bundle
  • Untartar xvf shared archive
  • CreateCreate IOPS — 4 KiB files
  • DeleteDelete IOPS (paths kept for BW)
  • Write / ReadBandwidth — 64 MiB files
  • Read+WriteOverlapped R+W at target rates
  • RIOPS1 GiB sparse · sequential random 4 KiB direct W then R (5× step)
  • Final deletePaced delete, then force wipe

Orange labels are optional; IO phases always run.

Load model

Ramps and rates

  • You set global create/delete rates and write/read bandwidth.
  • Each selected client gets global ÷ N participants.
  • Every IO phase ramps 10% → 100% in 10% steps (default 30 s/step), except RIOPS (5× step: writes then reads).
  • Delete adds an extra 100% sweep; final delete ends with a forced host-tree wipe.
  • Losing a run participant fails the run. Selection is locked while running.

Output

What you read back

Charts

IOPS and bandwidth vs expected grey lines; phase overlays; 60‑minute history.

Latency

Histograms for create, delete, 64 MiB R/W, software, git, untar — plus failures.

Results

Phase efficiency vs target, peaks, p95/p99; JSON and printable report export.

Header

Startup = first→last client connect span; Elapsed = run wall time.
